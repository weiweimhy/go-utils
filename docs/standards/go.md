# Go 开发标准

## 适用范围

本标准适用于根模块和全部 v6 扩展子模块。它将本项目的工具库边界与已采用的 Go 工程
约定结合起来；当标准与代码中已发布的兼容性契约冲突时，先保护既有公开行为并在变更中
明确说明。

## 包与 API 设计

- 一个目录一个职责明确的包；包名简短、可读，避免为了方便导入而形成循环依赖。
- 每个公开包保留准确的 `doc.go`。新增或修改导出标识符时，注释说明用途、默认值、限制、
  风险、错误和关闭语义，而不复述显而易见的实现。
- 优先用构造器、函数和小型 `Options` 公开能力。选项的零值和非零默认值必须可预测并有
  测试覆盖；不要用包级可变状态保存调用方请求状态。
- 只有机制已在多个独立场景中稳定复用时才加入工具库。领域校验、业务编号、策略和权威
  数据来源保留在消费方。

## 依赖与模块

- 根模块只使用标准库和本模块包。引入第三方依赖前，先验证它不能放在扩展子模块。
- 子模块的外部依赖只服务于其已声明的职责；不要因一次调用需求把平台 SDK 扩散到根模块。
- 模块路径必须保留 `/v6`。修改子模块依赖、替换规则或公开 API 时，同时审查该模块的
  `go.mod`、`go.sum`、测试和发布兼容性。

## 上下文与错误

- 网络、文件、重试、下载、并发任务及其他可取消阻塞链路必须接收并向下游调用传播
  `context.Context`；尽早返回取消或截止错误。
- 纯转换、格式化或无阻塞内存计算不为形式添加 `context`。
- 用 `%w` 包装底层错误并添加操作上下文。供调用方分支处理的错误使用哨兵错误或公开错误
  类型，并保持 `errors.Is`、`errors.As` 或 `Unwrap` 可用。
- 通用包默认不记录日志、不打印、不吞掉错误。不得把令牌、密钥、用户信息或完整敏感 URL
  放入错误、日志或测试失败信息。

## 并发与资源

- 只为共享可变状态加锁；锁内不执行网络 I/O、磁盘 I/O、用户回调或可能阻塞的 channel
  操作。
- 每个 goroutine 必须有明确的取消、关闭或完成路径。创建队列、工作池或订阅关系时，
  明确背压、panic 处理、提交失败与重复关闭的语义。
- 创建资源的一方负责生命周期。`Close`、`Sync`、响应体关闭等返回错误不得被无意忽略。

## I/O 与安全默认值

- 外部 HTTP 调用必须有上下文、超时、响应体关闭和大小限制；错误诊断先脱敏再返回。
- 处理不可信路径时使用受控目录、相对路径清理和既有 `pathutil` 边界工具；不要自行拼接后
  假定路径安全。
- 写入私有数据时使用安全权限和原子写入等明确选项；不得因为方便而降低默认安全性。
- JSON 或外部输入的宽容度必须是显式 API 选择。安全拒绝策略、大小上限和错误信息都要有
  回归测试。

## 测试与文档

- 新的公开行为至少覆盖成功、无效输入、依赖失败和默认值；并发与 I/O 另覆盖取消、关闭、
  上限与资源清理。
- 优先表驱动测试、`httptest`、测试临时目录和可注入时钟/客户端。测试必须可重复，不能
  依赖真实账号、网络服务、用户路径或时序猜测。
- 提交前按 [开发与验证说明](../development.md) 运行模块对应的格式、vet 和测试。根模块
  的并发改动还要通过 race 检测。
- 公共 API 或兼容性语义变化时，同步更新 `doc.go`、README、示例、测试和相关 `docs/`。
