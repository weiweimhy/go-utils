# 测试与质量

## 当前质量门槛

CI 在 Ubuntu 上对根模块和每个扩展模块分别执行：

```text
gofmt -l .   # 必须无输出
go vet ./...
go test ./...
```

CI 还只对根模块执行：

```text
go test -race ./...
```

仓库没有已声明的覆盖率阈值、静态分析器配置或发布自动化要求。不要在文档或提交说明中
声称它们已经存在。

## 现有测试层级

- 单元测试覆盖各包的公开行为与边界条件。
- `httputil` 测试覆盖状态码策略、响应体大小限制、URL 脱敏、请求错误和 JSON 请求。
- `event`、`task`、`streamutil`、`syncutil` 等并发包测试关闭、队列、竞争与并发访问语义。
- `fsutil`、`pathutil`、`securityutil`、`jsonutil` 等安全相关包测试权限、路径、长度限制、
  脱敏和严格解码边界。
- `localdb` 与 `task` 包包含可由 `go test` 执行的 Example；示例是公开用法的一部分。

## 新测试要求

变更必须在所属模块补齐紧邻实现的测试。至少覆盖：

- 正常路径和公共 API 的默认值。
- 无效输入、底层依赖失败和返回错误的可判断性。
- 取消、超时、关闭或重复调用等生命周期边界（适用于 I/O 或并发代码）。
- 新的安全边界，例如敏感信息、文件权限、路径解析和响应体限制。

网络代码优先使用 `httptest` 或可注入客户端；文件测试使用测试临时目录；不要依赖真实
外部账号、密钥、用户目录或非确定性的时间。并发测试必须等待 goroutine 完成，不能以
任意 `Sleep` 掩盖生命周期问题。

## 提交前检查

1. 对改动的 Go 文件执行 `gofmt -w`，再确认 `gofmt -l .` 无输出。
2. 在每个受影响模块执行 `go vet ./...` 和 `go test ./...`。
3. 变更根模块的并发、同步、事件、任务或共享状态时，执行 `go test -race ./...`。
4. 公共 API、默认值、错误、模块路径或安全语义变化时，检查 README、GoDoc 和 `docs/`。

## 高风险回归清单

- HTTP：超时、取消、非成功状态、响应大小、认证信息与 URL 脱敏。
- 文件与路径：目录逃逸、符号链接或 reparse point、权限、原子写入与写入失败。
- 并发：锁保护范围、关闭期间提交、队列排空、goroutine 退出及 panic 隔离。
- 兼容性：根模块不得意外引入第三方依赖，子模块的 `/v6` 路径和依赖边界保持正确。
