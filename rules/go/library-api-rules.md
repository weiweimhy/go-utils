# 项目规则（Project Rules · 去杂质重构版）

> 定位说明：
> 本文件是 **L2 级规则**，用于描述「本项目的形态、模块边界与不可变架构决策」。
>
> ❌ 本文件不包含具体代码写法
> ❌ 本文件不替代 Go / 前端技术规范
> ✅ 本文件用于 **约束项目形态，避免架构漂移**

---

## 1. 项目形态声明（不可变事实）

本项目是一个：

* **桌面应用**（非 Web 服务）
* 技术栈：

  * 后端：Go
  * 桌面框架：Wails
  * 前端：Vue 3

### 关键结论（强制认知）

* 本项目不是前后端解耦的分布式系统
* 前端与后端：

  * 进程不同
  * 生命周期强绑定
  * 通信成本低，但边界必须清晰

> 所有设计必须基于以上事实，而不是 Web / 微服务的惯性思维。

---

## 2. 模块划分原则（最重要）

### 2.1 模块分层（不可突破）

```
UI（Vue3）
│
├─ 调用接口（Wails Bindings）
│
Go 应用层（Application）
│
├─ 领域 / 业务逻辑
│
Go 基础设施层（Infra）
```

### 强制规则

* UI：

  * 不包含业务规则
  * 不保存长期状态

* Go 应用层：

  * 是业务唯一真相
  * 不依赖 UI 实现细节

* 基础设施层：

  * 只做技术能力
  * 不理解业务语义

---

## 3. 前后端边界规则（Wails 专属）

### 3.1 调用方向（单向）

* Vue → Go：✅ 允许
* Go → Vue：❌ 禁止（除框架事件）

> 后端永远不主动“操纵 UI”。

---

### 3.2 数据传输原则

* 只传递：

  * DTO / Plain Struct
* 禁止：

  * 传递函数
  * 传递复杂生命周期对象

---

## 4. 状态与职责边界

### 4.1 状态归属（强制）

* 长期状态：

  * 属于 Go

* 临时 UI 状态：

  * 属于前端

* 禁止：

  * 前端成为“业务状态源”

---

### 4.2 错误与异常

* Go 层：

  * 返回明确错误

* 前端：

  * 负责展示
  * 不做错误推断

---

## 5. 并发与性能基本立场

> 本项目默认是 **单用户桌面应用**。

### 结论

* 优先：

  * 可读性
  * 正确性

* 并发：

  * 只在 Go 层存在
  * UI 层不感知 goroutine

---

## 6. 配置与环境

* 配置读取：

  * Go 层统一负责

* 前端：

  * 只感知结果

---

## 7. 明确禁止的行为（红线）

* ❌ 把业务判断写在 Vue 中
* ❌ 为了“方便 UI”改后端模型
* ❌ 引入 Web 后端架构习惯（Controller / Middleware 滥用）
* ❌ 在规则文件之外私自约定“潜规则”

---

## 8. 本文件的边界（非常重要）

如果你发现：

* 在这里想写代码细节 → **放错地方了**
* 在这里想规定 UI 样式 → **去前端规则**
* 在这里想定义 Go 代码规范 → **去 go-project-rules.md**

---

**本文件的唯一使命：**

> **让项目在演进过程中，永远不偏离最初设定的架构轨道。**
